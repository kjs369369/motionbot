# 지식 파일(kb) 작성 가이드

kb는 `window.AICLAB_MBOT_KB = {...}` 를 정의하는 일반 JS 파일이다. 위젯이 `data-kb` 주소로 불러온다.
파일명은 `<사이트-짧은이름>.kb.js` (예: `astra.kb.js`, `aiclab-home.kb.js`).

## 구조

```js
(function () {
  var S = 'https://example.com';            // 사이트 기준 주소 (같은 페이지 앵커 판정에 쓰임)
  window.AICLAB_MBOT_KB = {
    hello: '첫 등장 말풍선 (40자 이내)',
    greeting: '창을 처음 열 때 인사. <b>굵게</b> 허용',
    placeholder: '입력창 예시 문구: 예: 세미나 일정, 문의 방법',
    quick: ['빠른 질문 6~8개', ...],          // 창 하단 칩. faq 키워드와 맞물리게
    tips: ['산책 중 말풍선 5~8개', ...],        // 20자 안팎
    fallback: '못 찾았을 때 답. 문의처를 함께',
    faq: [ { q: ['키워드', ...], a: 'HTML 답', title: '바로가기 이름', url: S + '/#contact', linkDesc: '', showItems: false } ],
    items: [ { kind: '분류', title: '이름', badge: '아이콘 글자', desc: '한 줄', url: '...', tags: '검색용 단어' } ],
  };
})();
```

## 필드별 요령

**faq** — 질문 의도별 고정 답.
- `q`: 사용자가 칠 법한 단어들. 질문 문장에 포함되면 매칭된다(부분 문자열). 여러 FAQ가 걸리면 **가장 긴 키워드**가 이긴다.
  → "임원"(넓음)과 "임원 가입"(좁음)을 함께 둬도 "임원 가입"은 가입 FAQ로 간다.
- **한 글자·두 글자 범용 키워드는 피한다.** 부분 문자열 매칭이라 "상"은 "대상·이상·상담"에, "대상"은 "공무원 대상 책"에 걸린다. "받은 상", "상 받"처럼 구로 쓴다.
- 같은 의도의 세부 경로(예: 일반 문의 vs 카카오톡 문의)는 더 긴 키워드("카톡으로", "카카오톡 채널")를 세부 FAQ에 넣어 이기게 한다.
- `a`: 답 HTML. 사이트 문장 그대로, 2~3문장. 연락처는 사이트에 공개된 것만.
- `url` + `title`: 답 아래 "열기" 버튼. 외부 링크면 "열기 ↗"로 새 탭.
- `showItems: false`: 답만 보이고 검색 결과 목록은 숨김. 정답이 하나뿐인 질문(문의처, 약관)에 쓴다. 이름 검색과 겹치는 넓은 FAQ("임원", "이사")는 `showItems`를 생략해 결과 목록도 같이 보이게 한다.

**items** — 검색 대상 목록. 사람·페이지·게시판·행사 하나하나.
- 제목이 질문과 맞으면 +5점, 설명·태그·분류에 맞으면 +1점. 상위 5개를 보여 준다.
- `tags`에는 사용자가 칠 단어를 넣는다(직함, 분야, 동의어). 사람이면 직함·소속·전문분야.
- `badge`: 동그라미 안에 보일 첫 글자. 생략하면 제목 첫 글자.
- 사람 목록은 헬퍼로 짧게: `var P = (name, role, desc, tags) => ({ kind: '임원진 · ' + role, title: name, desc, url: S + '/#people', tags: role + ' ' + tags });`

## 사실성 원칙
- 사이트에 실제로 적힌 내용만 쓴다. 사이트가 "초안", "확인 후 안내"라고 적었으면 그 표현을 유지한다.
- 사이트 안에서 숫자가 서로 다르면(예: 메타 "저서 25권+", 성과 카운터 "24+", 실제 목록 23권) 하나를 고르고 출처 영역을 밝힌다("성과 섹션 기준 24+"). 보고서에 불일치를 적어 사용자가 사이트를 정리하게 한다.
- 앵커(id)가 없는 영역은 가장 가까운 앵커나 외부 원본(유튜브 채널 등)으로 연결한다.
- 날짜는 사이트 표기 그대로("보도된 일정 2026.10.12"). 상대 날짜(내일, 다음 주) 금지.
- 파일 머리 주석에 출처 URL과 작성일을 적는다 → 나중에 갱신 시점 판단.

## 점검 체크리스트
- [ ] quick 칩을 하나씩 눌렀을 때 전부 의미 있는 답이 나온다
- [ ] 사람 이름 3개 이상 검색해 해당 프로필이 1순위로 나온다
- [ ] "문의", "가입", "자료" 같은 핵심 의도가 FAQ로 바로 답한다
- [ ] fallback에 연락 수단이 있다
- [ ] `node -e "require('vm').runInNewContext(require('fs').readFileSync('<kb>','utf8'),{window:{}})"` 로 문법 확인
